# 各環境版本現況

本文件是環境版本正本：記錄每個服務在每個環境「目前正在執行」的版本，是軍師對版本與環境現況的唯一記載處。軍師的其他文件寫到執行中版本時連結到本文件，不抄版本號。

建立方式：軍師第一次要引用某環境正在執行的版本而本文件不存在時，複製本骨架至 `docs/modules/各環境版本現況.md`，把 `<…>` 換成實際內容，刪除用不到的小節。沒有部署環境的專案群不必建立。

## 使用規則

- **每一列都是「最後查證」當日的事實，不是永久事實。** 引用前先看該列的「最後查證」日期。日期之後若有部署、升版或換映像，該列可能已過時。
- **據以做實作級判斷前重新查證。** 判斷「會不會壞」「能不能用某語法或功能」時，以該環境當下的實際狀態為準。查證方法寫在各節的「查證方法」，查證後更新該列。
- **引用措辭只有一種形式**：「依環境版本正本記載（查證日、來源層級）」。來源層級為實查的列，效力等同「已查」；其餘三級等同「未查」。
- **規劃約束不寫在本文件。** 例如「新程式碼以某主次版本為語法上限」屬於規劃約束，寫在軍師 `CLAUDE.md` 的環境限制段；本文件只記錄實際執行的版本（修補版號、映像 tag）。

## 來源層級

每一列的「來源」欄先標層級，再標位置。層級由高到低分四級：

| 層級 | 定義 | 能代表什麼 |
|---|---|---|
| 實查 | 有人在該環境實際執行查證指令、看到結果 | **唯一代表已部署事實的層級** |
| 原始碼 | 讀取子專案 repo 的版號檔或部署設定 | 只代表原始碼宣告的版本，不代表已部署 |
| 常駐文件 | 軍師或子專案常駐文件（playbook、README 等）的記載 | 二手資訊，未實查 |
| 回覆 | 交接回覆、上報或申請中由子專案 session 自述的部署結果 | 二手資訊，未實查 |

位置的寫法：

- 子專案內的檔案寫成「角色代碼＋repo 相對路徑」（例：`<角色代碼>` 的 `VERSION`），**不寫絕對路徑**。機器路徑的常設登記只存在於軍師 `CLAUDE.md` 的關聯專案表與全域註冊表。
- 回覆、上報與申請一律以完整檔名引用，不寫目錄；歸檔後檔名不變。
- 實查寫明查證方式（執行的指令或查看的位置）。

## 「最後查證」欄的日期語意

「最後查證」記錄該列事實被確認的日期：

- 來源層級為實查時，填實際在環境查證的日期。
- 來源層級為其餘三級時，填來源所記載的事實日期（例：回覆寫明的部署日、版號檔最後一次變更日），並在來源欄標明層級。**不填軍師讀到這份來源的日期**——那會讓讀者誤以為環境在當天被查過。
- 來源未記載日期時，填「未標日期」。

## <N+1>. 更新時機

- 交接回覆、上報或申請寫明「已部署」「已升版」「已換映像」時，於收尾當下更新對應列的版本、最後查證日期與來源；來源層級填「回覆」。
- 軍師 session 或使用者實查某環境的版本後，更新對應列，來源層級填「實查」並寫明查證方式。
- 某列的最後查證日期之後有已知的部署，但尚未取得新版本資訊時，在該列註記「可能已過時」。
- **某列的執行中版本更新後，回頭檢討軍師 `CLAUDE.md` 環境限制段中由該版本導出的上限**，過時的上限一併修正。上限由執行中版本導出，版本升了而上限沒改，軍師會繼續依舊上限寫交接約束。
