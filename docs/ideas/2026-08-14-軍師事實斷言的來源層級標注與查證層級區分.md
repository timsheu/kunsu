# 軍師事實斷言的來源層級標注與查證層級區分

源自 ebook 軍師 2026-08-14 事件（`docs/todos/軍師以中介文件代替原始碼查證導致傳遞錯誤事實斷言.md`）：軍師查閱 android 的 `pages-index.md`（中介文件）後，以「Android 端的事實是 2 頁」的語氣寫進交接，實際原始碼是 3 頁；用扣除法得到正確答案的 ios-app 反被說服改口。現行規範沒有區分「查中介文件」與「查原始碼」兩個查證層級——軍師範本 Invariant #2 視兩者為同一種唯讀查閱，工作流程第 2 步盤點優先序（handoffs → plans → 子專案文件）整條沒有「子專案原始碼」層；斷言語氣也不攜帶來源層級，接手方無從分辨幾手資訊。深層結構（android 端查證確認）：中介文件唯一的消費者是軍師——產線腳本（抽取、驗證）全部直讀原始碼繞過它，漂移不觸發任何紅燈，唯一受害者正是唯一信任它的角色；且轉述鏈上任何一環都無法分辨上游失真發生在哪段，除非回到源頭。「標明來源層級」已有一次正面樣本（軍師標注「本節事實轉引自回覆、未自行查證原始碼」後，ios-app 明確因此把核對升級到原始碼層級並抓到一處轉引失真），但該次混雜「剛看到軍師認錯」的前車之鑑因素無法歸因，且「轉引他人回覆」有天然來源意識、「查閱他方文件」沒有——後者正是出錯場景。候選落點兩個：(a) handoff add 指引（kunsu 語境）補「他方系統事實斷言須標來源層級；接手方會據以實作的斷言須落到原始碼」——單一副本、零遷移；(b) 軍師範本工作流程第 2 步盤點優先序補原始碼層＋Invariant #2 層級區分——動範本需三軍師遷移，成本較高。ebook 軍師 CLAUDE.md 的 Lumen schema drift 規則（以實際 schema 為準、migration 僅供參考）是同型規則的既有先例，一般化的風險是查證成本無差別上升，ebook 端傾向「依斷言用途分級」（背景說明可信中介文件、據以實作的事實斷言須落原始碼）但未驗證可操作性。單次樣本，成形後以 /ce-brainstorm 推進。
