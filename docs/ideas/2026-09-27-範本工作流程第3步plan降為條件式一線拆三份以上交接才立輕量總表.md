# 範本工作流程第3步plan降為條件式：一線拆三份以上交接才立輕量總表

來源：2026-09-27 依《Plan mode is dead》（Ayman Nadeem，2026-09-24）對 kunsu 的評估。文章論點「planning ≠ plan，把規劃變成文件產物是錯誤、使用者對長 spec 沒有胃口」在 ebook 軍師已自然成立：18 份 plan 全部集中 2026-07-03～08-21，8/21 之後約 140 份交接本體零新 plan；CLAUDE.md 已把 plans 降為「歷史意圖快照、價值最低」；iOS 兩條線（9 份＋8 份交接）從頭沒有 plan。範本工作流程第 3 步「以 ce-plan 寫入 docs/plans」與實況脫節，session 靜默跳過（指引失效的既知形狀）。

## 背景 / 動機

- 純交接鏈的代價已出現（`ebook/docs/solutions/documentation-gaps/handoff-series-scope-needs-an-index-not-cross-references.md`）：iOS 底層移植規劃八份交接，第四至八份的範圍只存在於前面交接的交叉引用與「明確不要做的事」裡；唯一說明「第四份＝書籍瀏覽與書架」的那句隨停車紀錄覆寫消失，只能靠 git show 取回；「還剩什麼沒做」必須翻遍所有交接、回覆與停車紀錄。其 Guidance：「一條工作線拆成三份以上交接時，先立一份總表，再發第一份交接」。
- 文章沒說的後果：AI 自行決定不規劃時，總表與查核靜默消失。kunsu 不採「全對話式取消規劃」——交接是跨 session 的訊息與契約，接手方在另一 context 無法即時迭代；跨 repo 的重做成本含協調成本（既有 idea `docs/ideas/2026-09-03-交接前置規劃深度的張力UncleBob反SDD論點對照跨repo介接規格前置.md` 已記兩面證據）。

**候選改法**（範本層，kunsu-init）：
- 第 3 步改為條件式：單份或兩份交接可解的需求不立 plan；一條線拆 ≥3 份交接才立「線總表」——最小欄位為份次清單（後段暫定亦列）、每份範圍摘要、相依順序（可與 `depends_on` 交接依賴圖互相指涉）。
- 總表不是 spec：不寫介接規格細節（那是各份交接本體的事），只回答「總共幾份、每份負責什麼、誰依賴誰、還缺哪幾份」。
- 落點待定：沿用 docs/plans（既有 dataview／kb 索引路徑）或另立輕量檔；與 B 方向「還缺什麼」視圖合場——總表是其資料來源之一。
- 三 live 軍師（ebook／ivm／px）需一波遷移；consistency-check H 鏈比對字串「規劃前既有盤點」所在句附近，改動時注意錨句。

同批評估：A 方向（軍師提問時三信箱新件提示 hook）已於同日進 ce-brainstorm／ce-plan：`docs/plans/2026-09-27-1232-feat-kunsu-prompt-inbox-notice-plan.md`；B 方向見 `docs/ideas/2026-09-27-還缺什麼視圖軍師欠辦行動項與工作線剩餘範圍的可見性.md`。
