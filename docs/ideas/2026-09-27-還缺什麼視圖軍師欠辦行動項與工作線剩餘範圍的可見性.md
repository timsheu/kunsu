# 「還缺什麼」視圖：軍師欠辦行動項與工作線剩餘範圍的可見性

來源：2026-09-27 依《Plan mode is dead》（Ayman Nadeem，2026-09-24）對 kunsu 的評估。文章承認未解的問題是「agent 變多時，人類注意力該放在最少的幾個地方、並附足夠上下文」；對照 ebook 軍師紀錄，沙盤／kunsu-inbox／SessionStart hook 目前只涵蓋「進來的訊息」（回覆、上報、申請），三類東西不在任何視圖：軍師欠自己的行動項、久懸件的內容（只傳達「還沒收尾」不傳達「內容物已完成」）、一條工作線的剩餘範圍。

## 背景 / 動機

- ebook 補跑 done 查核盤點報告（2026-08-29）：軍師自身行動項確實蒸發，兩筆完全無任何落點；軍師流程缺口研究：「它偵測『有新東西進來』，不偵測『有東西該出去』」「懸空六天沒有任何環節提示『你欠自己一件事』」。
- 2026-09-01 iOS WebSocket 七事件：正確答案（實作全完成、僅三項驗收需真推播）在 replies/ 躺八天，久懸「已回覆待確認」件只傳達「還沒收尾」，session 據 android 回覆隻字片語外推 iOS 現況，差點重複派發；同軍師 2026-08-31 devicename 已真實發生一次重複派發。既有 idea `docs/ideas/2026-09-01-久懸已回覆待確認件於沙盤與inbox摘要列帶回覆結論首句.md` 已涵蓋「結論首句」這一子項，本 idea 是其外環。
- handoff-series-scope solution：純交接鏈答得出「做過什麼」、答不出「還缺什麼」；線的剩餘範圍只靠前面交接的「明確不要做」承載。
- 量化：ebook 頂層 37 份未收尾交接中 21 份零回覆、年齡中位數 27 天，7 份為更正／裁示型——軍師派出去等於做完的形狀，沒有視圖區分「等對方」與「等自己」。

**候選面向**（顯示層，分類邏輯與 handoff 協議零改動）：
- 沙盤與 kunsu-inbox 軍師模式加「軍師欠辦」段：回覆內指向發起方的行動項（v0.12.0 反向路由查核只在 done 當下報，無狀態、不累積）、已裁示未派發的更正。
- 久懸件摘要列帶回覆結論首句（既有 idea）。
- 工作線剩餘範圍：與 C 方向（條件式線總表）合場，總表是這個視圖的資料來源之一，但本視圖不等總表也能先做前兩項。

同批評估拆出的 A 方向（軍師提問時三信箱新件提示 hook）已於同日進 ce-brainstorm／ce-plan：`docs/plans/2026-09-27-1232-feat-kunsu-prompt-inbox-notice-plan.md`（其 How This Work Fits Together 段記錄三方向關係）。
