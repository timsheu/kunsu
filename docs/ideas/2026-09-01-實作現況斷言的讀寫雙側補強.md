# 實作現況斷言的讀寫雙側補強

軍師對子專案「實作現況」的斷言出過實證錯誤（讀文件下結論、經使用者質疑後查原始碼才更正），補強分讀寫兩側，兩件一組落地。

## 背景 / 動機

實證事故（2026-09-01 ebook 軍師 session）：使用者問「公告訊號模式完成了嗎」，軍師依 backend 回覆自陳＋08-22 交接「不含實作」下結論「未完成」，經使用者記憶矛盾質疑後查原始碼，確認已完成、結論作廢。

診斷（非機制缺席，是掛載點覆蓋缺口）：
- 斷言層級紀律（handoff v0.15.0）已明文「中介文件＝二手、據以實作級須一手落原始碼」，但掛載點是 add（寫交接時）、done 步驟 9（斷言自查附句）、規劃前既有盤點（工作流程步驟 2）——「對話中回答實作現況」三個路徑都不經過。與 v0.15.0 已知失效形狀同型（自身狀態誤報 11 實 7 也發生於對話回報時刻），但「子專案實作現況」無等價腳本可掛觸發詞，現況權威是原始碼、查證是開放式行為。
- 範本「自身狀態不憑記憶」原則句範圍明文限「自身 repo 狀態的具體數字或清單」，不涵蓋子專案實作現況。
- 加重因素：查證義務分級（對話評估易自判非據以實作級→不查）；宣告≠現況時效陷阱（08-22 交接「不含實作」是時點快照，其後實作已發生——與 v0.15.0 創始事件查 pages-index.md 當查證同族）。

## 讀方補強（治本次事故根因）

軍師範本副官慣例區加一句姊妹句（比照「自身狀態不憑記憶」）：「子專案實作現況以原始碼為準；僅讀文件作答時，措辭標明『依 X 記載、未查原始碼』」。落點＝熟練 session 必經的 CLAUDE.md 載體（v0.16.0 觸及率教訓），一句話、零流程改動、涉三 live 軍師遷移。

## 寫方補強（降查證成本，與讀方互補）

回覆方涉及程式碼改動時附「主要修改檔案路徑」清單：
- 既有條文已有一半：reply 步驟 2「盡量附可查核證據（測試輸出、日誌摘要、commit hash 或 檔案:行號）」（SKILL.md:265-266）——但只活在 SKILL.md，接手方手動寫回覆不經過；接手方必經文本是交接本體尾端「回覆方式」定型文字（new-handoff.sh 產生、腳本載體 14/14 從未失效），目前對證據隻字未提。
- 升級形態：定型文字加一行「涉及程式碼改動的回覆，請附主要修改檔案路徑清單」；SKILL.md reply 步驟 2 同步由「盡量」升格為條件式結構要求。查證從全庫搜尋變定點抽查，成本降一個量級，對話時刻順手查的機率才會實際上升——與副官契約「證據原文＋檔案:行號」同一哲學。
- 條件式必要：答疑、拒絕、blocked、暫離回報（最小三要素慣例）不涉程式碼改動，無條件要求是噪音。
- 成本：定型文字兩副本逐字一致（printf＋SKILL.md 範例段，consistency-check C 項罩得住）；定型文字漸長，只加一行並指回 SKILL。

## 誠實的限制

- 修改清單仍是宣告層快照：若完成事實從未寫進任何回覆、或軍師沒讀到該回覆，寫方條款救不了——讀方句才治「把過期宣告當現況」。
- 兩件一組落地，單做任一側都留缺口。
