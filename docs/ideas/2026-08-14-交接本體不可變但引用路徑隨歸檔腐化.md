# 交接本體不可變但引用路徑隨歸檔腐化

源自 ebook 軍師 2026-08-14 事件（`docs/todos/交接本體不可變但其引用路徑會隨歸檔失效.md`）：交接發出時必然引用剛收到的回覆（那正是發交接的依據），彙整完隨即收尾又把該批回覆歸檔至 archive/，引用路徑必然失效；依 Invariant #5 本體不可編輯，失效無法修正。兩步順序不可調換（不可能先收尾再發交接），故屬流程必然而非偶發，不需實例查證即可判為 kunsu 系統層面。`/handoff done` 步驟 8 的連結修正 grep 會命中交接本體但流程要求跳過——偵測到了、無法處置，是「本體不可變」對「引用正確」的刻意取捨，但後果此前未被記錄評估。現行低影響（接手方搜檔名幾秒可解）來自「歸檔只換一層目錄、檔名不變」的實作細節而非機制設計：歸檔若涉改名、目錄結構若調整（archive/ 依年月分層）、或接手方是解析引用清單的自動化流程，全部硬失敗；失效比例隨時間單調上升，且「引用當前正在處理的東西必失效、引用歷史才安全」恰與引用價值成反比。候選方向三個：(a) 引用慣例改寫檔名不寫完整路徑（或「檔名＋歸檔前位置」格式）——失去可點擊性但零 Invariant 改動，ebook 端認為成本最低；(b) Invariant #5 例外擴大到機械性路徑更新（同 status 例外的單一作者自洽性，但例外擴張會逐步空洞化定案快照語意）；(c) 接受現狀僅記錄。與既有 idea `2026-08-13-交接本體錯誤的勘誤落點與不可變性張力.md` 同是 Invariant #5 張力面——一個「內容錯不能改」、一個「內容對但引用失效」——屬 ADR 層級，建議合場一次 /ce-brainstorm 定奪。附帶一併評估：同輪收尾的 sed 批次修正因 `YYYY-MM-DD-標題.md` 命名不帶歸檔狀態，誤改仍在頂層的交接路徑（複驗抓回），命名的字串不可區分性與方向 (a) 直接相關。
