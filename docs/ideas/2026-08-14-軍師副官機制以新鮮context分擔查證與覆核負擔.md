# 軍師副官機制以新鮮context分擔查證與覆核負擔

源自使用者 2026-08-14 假設——ebook 三份研究文件的軍師端失誤可能是 session 負擔太大所致。證據分層檢驗：過載特徵明顯者三件（憑記憶報信箱狀態 11 實 7、查 `pages-index.md` 當查證、剛沉澱教訓同日憑常識填空），皆發生於彙整時刻（同讀多份長回覆、跨 3–4 子專案寫下輪交接、跑 done 四道查核，長 context 多線合成正是具體細節最易失真的條件）；但行動項漏接屬結構性非過載（v0.12.0 已補）、填空型錯誤子專案 session 也犯過（ebook 事件一），故定位為「過載放大錯誤率、資訊層級不可見使錯誤能傳播」兩因並存、分開治理。副官＝軍師 session 以 Agent tool 派新鮮 context subagent 分擔高成本查證——改變成本結構而非增加義務，符合 harness 不做枷鎖前提：主 context 內「落原始碼」很貴所以軍師選了中介文件，派副官後邊際成本趨近零，且新鮮 context 沒有累積敘事的偏見。兩個候選形態：(1) 查證副官——對他方系統做事實斷言前派遣落到原始碼，回傳證據原文＋`檔案:行號`（不回傳轉述結論——防轉述鏈再加一層失真，ebook 文件二證據二教訓）；(2) 覆核副官——交接發出前以新鮮 context 對草稿逐條斷言做對抗性核對（事件五密碼欄位錯誤即「發出前的新鮮眼睛」可攔、事後靠接手方比對關卡才攔到的類型）。可平行派多個（依子專案或斷言批次分工）。零新工具：Agent tool 現成、軍師唯讀權限副官直接繼承、純軍師範本慣例即可落地，Invariant 1 零觸碰；派遣指示須明訂以正體中文回覆（全域 subagent 規範）。與 `docs/ideas/2026-08-14-軍師事實斷言的來源層級標注與查證層級區分.md` 同屬軍師端防線、宜合場 brainstorm——副官查證後斷言即為一手資訊，未派副官時來源層級標注仍適用，兩者互補；接手方矛盾回報 norm 為末端防線，另場處理（三線互補不互相替代）。待評估：token 成本、派遣時機判準（每斷言 vs 僅接手方會據以實作的高風險斷言）、軍師範本工作流程的落點與措辭。
