# 軍師沙盤（kunsu dashboard）

同時開多個軍師／子專案視窗時，kunsu-inbox skill 得逐一切換視窗手動執行才知道有沒有新訊息，視窗一多容易顧此失彼。**軍師沙盤**（如統帥推演戰局的沙盤）是一個獨立的本機 FastAPI 服務，首頁是看板：每個軍師一張，每份尚未收尾的交接掛在「下一個要動作的角色」底下，一眼看出球在誰手上；另有完整彙整頁與 archive 頁。

**這不是可觸發的 skill**（Claude Code 與 Codex 皆以 frontmatter 原生旗標停用選用），不透過任何觸發語啟動，由使用者掌握啟停（前景手動啟動，或使用者親手安裝只含 `RunAtLoad` 的 LaunchAgent 於登入時啟動，見 [ADR 020](../adr/2026-10-01-adr-candidate-020-dashboard-login-autostart.md)；無背景輪詢，對所有 repo 唯讀）——這是本工具組「純 skill＋範本」原則的唯一例外，例外範圍界定詳見 [ADR 010](../adr/2026-07-11-adr-candidate-010-dashboard-service-exception.md)。

## 安裝與啟動

```bash
cd skills/kunsu-dashboard          # 或部署目錄：~/.claude/skills/kunsu-dashboard（Claude Code）／~/.agents/skills/kunsu-dashboard（Codex）
pip install -r requirements.txt    # 首次安裝，需 Python 3.10+
./start.sh                         # 預設 http://127.0.0.1:8000/（看板）
```

重新整理瀏覽器頁面即觸發全新掃描，不跑背景服務；要停止服務直接在終端機 Ctrl-C。

## 頁面一覽

| 路由 | 用途 |
|---|---|
| `/`（`/?k=<軍師目錄名>`） | 看板：所選軍師的持球者泳道 × 狀態欄 |
| `/overview` | 完整彙整頁：所有軍師與子專案的分組明細、異常、依賴圖與待辦技術債（原首頁） |
| `/archive?k=<軍師目錄名>` | 已完成（archive）：所選軍師已歸檔的交接 |
| `/handoff?k=<軍師目錄名>&f=<相對路徑>` | 全文頁：單份交接／申請／上報的 Markdown 渲染與同串回覆（舊→新） |

`k` 只接受註冊表中的軍師目錄名，不符時改顯示第一個軍師並提示；不帶 `k` 時顯示目錄名排序第一的軍師。

## 看板（首頁）

### 泳道與欄位

縱向泳道是**持球者**：軍師本身置頂，其下依角色代碼字母序列出該軍師的每個子專案角色。橫向是四個狀態欄：等待中、待辦、進行中、待驗收（不設完成欄，完成的交接在 archive 頁）。

| 交接狀態 | 放在哪 |
|---|---|
| 尚無回覆，且依賴（`depends_on`）尚未滿足 | 收件角色・等待中，卡片標「等：前置交接標題」 |
| 尚無回覆 | 收件角色・待辦 |
| 最新回覆 `partial` 或未知值 | 收件角色・進行中（未知值另標原始 status） |
| 最新回覆 `blocked` | 軍師・進行中，標 ⛔ 卡關（卡關通常需要軍師協調） |
| 最新回覆 `submitted` | 軍師・待驗收，標驗收方式（verify） |
| 新申請、新上報（未 commit 的信箱新件） | 軍師・待辦，標「申請」或「上報」 |

已有回覆但依賴未滿足的交接照回覆狀態放欄，卡片上仍標所等待的交接。欄內依停留基準日由舊到新排列；單一格子超過 8 張時，其餘收進「另有 N 筆」。

### 卡片

卡片以交接標題為主（不顯示檔名），標題過長截為兩行。下方小欄位：驗收方式、收件角色（軍師泳道的卡片）、停留天數（未接手自派發日起算、有回覆自最新回覆日起算、信箱件自投遞日起算）、線別（有宣告 `series` 時）與回覆摘錄。點「全文」開啟獨立全文頁（`/handoff`），卡片本身不內嵌本體與回覆。

### 頁首與警示列

頁首依序是軍師切換、已完成（archive）連結、技術債筆數（連到完整彙整頁該軍師分組）、完整彙整頁連結與掃描時間——久開的分頁可由掃描時間判斷是否需要重新整理。

有異常時看板頂端出現一行紅色警示，逐類列出筆數並連到完整彙整頁：軍師路徑失聯、tripwire、掃描腳本錯誤、未知收件角色、交接解析錯誤、依賴圖異常、已標 done 未歸檔、回覆自標 done。tripwire 或腳本錯誤時會加註「新申請／新上報清單可能不完整」。異常的交接不上看板。

沒有任何待處理項目且沒有異常時，看板只顯示一行「目前沒有待處理的項目」。

## 已完成（archive）頁

依檔名日期由新到舊列出已歸檔交接的標題、收件角色、更正交接（`corrected_by`）與「已歸檔未標 done」異常標記。每筆標題即全文頁連結，列表本身不內嵌全文。

## 全文頁（/handoff）

看板卡片與 archive 列表的「全文」連結開啟 `/handoff?k=<軍師目錄名>&f=<相對軍師根目錄的路徑>`：上方為 frontmatter 鍵值表，中段為交接本體的 Markdown 伺服器端渲染（markdown-it-py，CommonMark＋表格），交接另列依賴區塊（`depends_on` 各項的標題與是否已完成、`corrected_by`）與同串回覆（依 `in_reply_to` 比對，舊→新，各附 status／verify／created）；申請與上報只渲染本文。頁面維持零 JS、只回 text/html。

- `f` 只接受四個目錄（`docs/handoffs/`、`docs/handoffs/archive/`、`docs/applications/`、`docs/reports/`）底下的單層 `.md` 檔名，含 `..`、反斜線、多層目錄、其他目錄或不存在的檔案一律回 404，並以實體路徑核對擋 symlink 逃逸；`k` 不命中軍師也回 404（不像看板會退回第一個軍師）。
- 原文中的 HTML 標籤一律轉義為文字，`javascript:` 等協定的連結不會成為可點連結。
- 未安裝 markdown-it-py 時降級為純文字 `<pre>` 並顯示提示句，不影響其他頁面。
- 全文頁純讀檔，不執行信箱掃描腳本。

## 完整彙整頁（/overview）

原首頁原封不動搬到 `/overview`，頂端多一個「回看板」連結。

### 快速導覽

頁面最上方列出所有軍師與其子專案的目錄名連結，每個軍師一行；點擊即跳至該軍師分組或子專案卡片，分組若處於收合狀態會由瀏覽器自動展開（錨點掛在 `<details>` 內容區，零 JS）。子專案名後附 ⚠N（未接手件數）／⛔N（卡關件數）提示，stale 的軍師或子專案以灰字標示但仍可跳轉。

### 全域總覽列

頁首先給出跨軍師的整體態勢：⚠ 未接手・⛔ 卡關・⚡ 馬上可測・其餘待確認・📨 新訊息・待辦 N，另含 tripwire／腳本錯誤的軍師計數；全部為零時整列不顯示。

### 軍師分組與子專案巢狀

依軍師分組、子專案巢狀顯示在所屬軍師底下；分組收合列帶出子專案待處理計數（未接手／部分完成／待確認／異常，僅列非零項）。有進度或有未接手／異常件的軍師預設展開、健康且無新訊息者預設折疊——未接手件絕不會藏在收合分組裡。

### 交接分類與明細

每個子專案的交接依最新回覆分為三類：

- **⚠ 未接手（無回覆）**：以醒目標題呈現。
- **部分完成**：最新回覆 `status` 為 `partial`／`blocked`（另標 ⛔ 卡關）或未知值。
- **已回覆待確認**：依回覆 `verify:` 欄位拆成子分組——⚡ 馬上可測 → 📱 需實機測試 → 🚀 需上線測試 → 自由字串各 distinct 值一組 → 未標示驗收方式。愈接近「現在就能以 handoff skill 的 done 子指令收尾」的排愈前，組內等最久的陳年件排最前；每筆附 verify 推導的白話下一步提示與停留天數（自最新回覆日起算）。

每筆交接／訊息可展開（原生 `<details>`，零 JS）看完整 md 內容與最後修改時間；軍師的新回覆／新申請／新上報三個分類標題列各顯示「最新」時間。

### 待辦技術債卡片

彙整軍師自己 `docs/todos/` 頂層的技術債：未處理項依 severity 排序顯示標籤；「看似完成未歸檔」（`status` 已是已解決／已封存、檔案卻仍留在頂層）獨立子區塊提醒收尾；另計 `archive/` 已歸檔筆數。全域總覽列與軍師分組摘要列僅在非零時顯示「待辦 N」。

## 設計邊界

- **唯讀**：只讀取檔案系統與 git 狀態，不寫入任何 repo。
- **無背景輪詢**：只有重新整理頁面才掃描。看板只跑申請／上報兩支掃描腳本（不跑 scan-replies.sh——看板不用新回覆清單，而該腳本會推進歷史夾帶偵測基線），回覆側 tripwire 以完整彙整頁、`/kunsu-inbox` 與 SessionStart hook 為準。
- **使用者掌握啟停**：前景手動啟動，或使用者親手安裝的 LaunchAgent 於登入時啟動一次（只允許 `RunAtLoad`，不設 `KeepAlive` 等任何重啟或排程路徑；安裝與解除指令見 SKILL.md「登入自動啟動（選用）」）。
