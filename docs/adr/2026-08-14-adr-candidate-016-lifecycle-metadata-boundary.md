# ADR 016：Invariant #5 例外邊界重述為「內文不可變；frontmatter 生命週期 metadata 由發起方維護」

> 狀態：**Candidate**（待使用者審定；源自 [2026-08-14 Invariant #5 需求文件](../brainstorms/2026-08-14-invariant5-lifecycle-metadata-requirements.md)，該文件經 3-persona doc review 收斂）。

## Context

Invariant #5 規定交接文件本體為定案快照、任何人不再編輯，唯一例外是 `/handoff done` 收尾時的 `status` 更新與歸檔搬移。範本原文已把此例外定性為「作者自己對文件的**生命週期標記**……不改內文，單一作者原則不變」——邊界的原則性形狀其實已經存在，只是明文只列了 `status` 一個欄位。

兩個同源缺口使明文化成為必要（ebook 軍師研究文件記錄，2026-08-14）：

1. **勘誤落點**：已歸檔交接被發現內容有誤（密碼欄位方向寫反），錯誤原封留存 `archive/` 成為未來讀者的錯誤參考；回覆信箱是接手方單向管道，軍師無法寫入更正。「更正交接」已是田野實務（ebook 實發兩份），缺的只是從錯誤本體**指回更正**的指標。偵測側已由矛盾回報指引（handoff v0.13.0）與反向路由查核補完，缺口收窄為「錯誤確認後，未來讀者如何從本體找到更正」。
2. **引用腐化**：發新交接必然引用剛收到的回覆（發交接的依據），彙整完隨即收尾把該批回覆歸檔，引用路徑必然失效；順序不可調換，屬流程必然。兩種失效形狀的修復可能性同為零：引用**回覆路徑**者不在 done 步驟 8 的 grep 偵測範圍內（固定字串僅涵蓋本體與 todo 路徑），屬未偵測即失效；引用**原交接本體路徑**者會被 grep 命中，但處置受 Invariant #5 限制。

## Decision

1. **例外邊界重述**：交接文件本體的**內文**不可變；frontmatter 的**生命週期 metadata** 由發起方（文件作者）維護。這是既存例外定性（「生命週期標記」）的明文化，非開新例外。
2. **欄位擴張判準**（防滑坡，新欄位須經 ADR 修訂納入）：僅限發起方對自己文件的**生命週期事實標記**（狀態、指向後續文件的指標）；不承載內容判斷；不進掃描、tripwire、分類等任何比對邏輯；僅供 display 與追溯。
3. **現行合規欄位窮舉**：`status`（既有）、`corrected_by`（本 ADR 新增，選填）。
4. **勘誤慣例**：勘誤以**更正交接**傳遞（一般交接，標題建議「更正」開頭，指名被更正檔與錯誤點），不編輯原本體內文；發更正交接當下，發起方在原本體 frontmatter 補 `corrected_by: <更正交接檔名>`——值存**檔名不含路徑**（與引用慣例自洽，指標本身免疫歸檔腐化）；單值起步，出現第二份更正時改為 YAML 列表累加（保留完整更正歷史；此為隨 ADR 定案的設計層值形，消費端 display-only 無相容性面）。原本體已歸檔時同樣適用（例外係作者對自己文件的生命週期標記，位置無關）。
5. **引用慣例**：交接內文引用其他交接／回覆時必含**完整檔名**（含日期），路徑為當下位置提示、非權威識別；歸檔造成的路徑失效不構成錯誤，讀者以檔名搜尋定位。既有 `archive/` 失效引用不回溯修正。done 步驟 8 隨本 ADR 補一行明文：grep 命中交接本體（含 `archive/` 內）時**不修正、僅回報**供追溯（依 Invariant #5）——現行跳過行為只存在於憲章隱含約束、步驟字面無此規則，且 archive 內本體被 Edit 會被掃描靜默放行，須升為步驟字面規則消除 session 行為分歧空間；其餘範圍零改動。
6. **掃描機制相容性（零腳本改動）**：`corrected_by` 的 Edit 產生的 porcelain ` M` 中間態分兩種形狀——**頂層**本體落入 `scan-replies.sh` catch-all tripwire 範圍，沿 done 步驟 4–7 連續執行約束先例以同型約束（Edit 至確認 commit 間不執行 `/kunsu-inbox`）收斂；**archive 內**本體由歸檔區靜默略過分支（最先評估）涵蓋，無 tripwire 疑慮。不擴 rename 豁免形狀。

## Consequences

- **正面**：archive 內的錯誤本體帶有指向更正的可追溯指標，未來讀者不再把錯誤內容當正確參考；引用失效自「錯誤」重定義為「提示過期」，數十份既有交接的腐化不再是待修清單；「定案快照」語意以明文邊界收緊而非鬆動——內文永不可變，例外收攏在可窮舉的 metadata 欄位表內。
- **負面／限制**：讀者需看 frontmatter 才知有更正（沙盤顯示 `corrected_by` 列後續評估）；`corrected_by` 由手工 Edit 維護，列表縮排寫壞會使 YAML 解析失敗、頂層本體被沙盤降為缺欄位異常（archive 內無此風險）——屬使用錯誤情境；欄位擴張判準依賴後續 ADR 紀律執行。
- 對原始目的**零損害論證**：Invariant #5 防的是版本漂移（雙方共編同一檔案）。本重述維持「任何檔案永遠只有一個作者」——metadata 僅發起方寫、內文誰都不寫；接手方的管道（回覆信箱）零改動。

## Alternatives considered

- **corrections/ 目錄（對稱 replies/）**：內文與 frontmatter 都絕對不動，但掃描腳本、沙盤、範本、歸檔形狀全要認識新目錄、三 live 軍師遷移，且本體仍無指標——讀者還是要自己去翻目錄。成本換不到指標能力。不採。
- **本體追加勘誤節**：錯誤旁邊就是更正、讀者體驗最直接；但內文一旦可 append，「定案快照」語意開始空洞化，正是 Invariant #5 要防的。不採。
- **接受現狀僅記錄**：零成本；代價是 archive 錯誤永存無指標、引用持續腐化，且「偵測到但無法處置」（done 步驟 8 對本體）已實測會重複發生。不採。
