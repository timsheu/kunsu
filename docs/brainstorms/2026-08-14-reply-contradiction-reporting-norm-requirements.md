# 接手方矛盾回報規範——需求文件

## Summary

在 `/handoff` reply 步驟 2 新增一段帶理由的矛盾回報規範：接手方發現交接內容與自己所持參照物不符、或交接內文自相矛盾時，即使判斷不影響自身實作也在回覆中明列。命中才報、單一副本、兩種語境通用、零遷移；讀方承接沿用既有反向路由查核，不新增任何強制查核或互動。

---

## Problem Frame

現行 reply 協議沒有任何地方要求接手方回報「交接內容與原始來源矛盾」。ebook 軍師 2026-08-13 事件五是實例：軍師交接把 register／forgot-password 兩頁的密碼欄位方向寫反（憑常識推論填補了回覆未載明的細節），接手方 `ios-app` 依封包原文實作做對了，但回覆只填自己的實作內容、未標註與交接所述不符，軍師靠彙整時人工比對兩份表格才察覺。

這是訊號缺席型缺口，與 2026-08-13 收尾查核系列處理的類型互補：反向路由查核屬讀方查核，讀不到沒寫的東西；當時否決寫方標記的理由「寫方訊號從來不缺」只對行動項與答案類成立，矛盾類的寫方訊號正是缺席的。風險兩分支都有代價——接手方照交接做，錯誤落地；照原始來源做，軍師的錯誤認知存活於定案快照，可跨交接流傳。

田野證據支持補上這個訊號：ebook 軍師自 2026-08-13 起在交接的期望交付自行加入「發現不符請明確指出」項，四次實施全數被執行；2026-08-14 首次實質命中——`ios-app` 指出交接中一處數字不一致，判斷不影響結論仍回報，軍師順查揭出中介文件的實質錯誤與軍師傳遞的錯誤事實斷言，價值遠大於命中點本身。記錄下的生效條件有三：關卡會抓到真實問題、命中價值可能大於命中點、接手方即使判斷不影響結論也照樣回報是機制生效的關鍵。

本次設計受使用者 2026-08-14 定調的前提約束：現有模型能力已高，harness 不應成為枷鎖——機制優先信息補全與帶理由的規範，讓模型從 rationale 泛化，不採行為強制。

---

## Key Decisions

- **帶理由的規範，不採行為強制**：不強制每份回覆附核對結果、不強制正面確認段（「一律回報」形態經評估否決）。接受沉默無法區分「沒矛盾」與「沒核對」；田野證據顯示回報行為源自規範被說出且附了理由，不是表單欄位逼出來的。規範文字自帶結構事實（接手方是唯一同時持有交接與參照物的一方）與後果（錯誤認知會跨交接流傳），信任接手方判斷核對深度。
- **單一副本掛 reply 步驟 2 必經路徑**：不進交接定型文字（避免 `new-handoff.sh` printf 與 SKILL.md 範例段的第二文案副本與 consistency-check 同步成本）、不動軍師範本（零 live 軍師遷移）。接手方產出回覆必經 `/handoff reply`，掛載點即攔截點。
- **兩種語境通用**：kunsu 語境與本地語境都適用，步驟 2 不加語境分支。本地交接的發起方同樣會把錯誤認知寫進定案快照。
- **讀方承接沿用反向路由查核**：回覆中的矛盾指摘屬「指向發起方的行動項」，done 收尾時由既有查核接住並提示落點，不新增 done 查核項。

---

## Requirements

- R1. reply 步驟 2 新增一段矛盾回報指引，涵蓋兩類情形：交接內容與接手方所持參照物（原始碼、原始文件、實際狀態）不符；交接內文自相矛盾（例如數字對不上、前後段互斥）。
- R2. 指引明訂「即使判斷不影響自身實作也在回覆中明列」，並自帶理由：接手方是唯一同時持有交接與參照物的一方，未被指出的錯誤認知會留存於定案快照並跨交接流傳。
- R3. 指引為命中才報：不要求每份回覆附核對聲明、不新增回覆格式欄位、不強制核對範圍與深度。
- R4. 指引兩種語境通用，不設語境分支；暫離回報的最小內文三要素不受影響。
- R5. 零改動邊界：回覆檔格式與 frontmatter、`new-handoff-reply.sh`、交接定型文字、軍師範本、掃描與 tripwire 邏輯、done 流程皆不動。版號依慣例升 handoff minor，kunsu-inbox 依賴聲明同步。

---

## Acceptance Examples

- AE1. **Covers R1, R2.** 接手方核對時發現交接表格數字加總不一致，判斷不影響本輪交付 → 回覆仍明列該不一致並附位置（2026-08-14 田野命中的重演場景）。
- AE2. **Covers R3.** 接手方完成工作、未發現任何矛盾 → 回覆不需任何核對聲明，協議不因缺少而視為不完整。
- AE3. **Covers R4.** 本地語境交接（同 repo 前端交後台），接手方發現交接引用的既有行為描述與實際程式碼不符 → 同樣在回覆中明列。

## Scope Boundaries

- 軍師端兩道防線另場處理：查證／覆核副官（`docs/ideas/2026-08-14-軍師副官機制以新鮮context分擔查證與覆核負擔.md`）與來源層級標注（`docs/ideas/2026-08-14-軍師事實斷言的來源層級標注與查證層級區分.md`），兩者同屬軍師端、宜合場 brainstorm。
- 矛盾被回報之後的承接（交接本體勘誤落點，涉 Invariant #5）屬 ADR 層級既有 idea（`docs/ideas/2026-08-13-交接本體錯誤的勘誤落點與不可變性張力.md`），本場不碰；被回報矛盾的當下處置沿用反向路由查核的「提示落點、使用者裁決」。
- 模型分工調整（子專案改用較低階模型以減少此類狀況）——評估後不採：文件記錄的失誤全數出自軍師端，接手方的主動查證與據實回報正是唯一生效的防線，降低接手方能力會削弱而非改善。
